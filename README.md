# 小テスト記録アプリ（Firebase版）

最終更新：2026年10月12日

---

## 1. 目的

5クラス約210人の小テストの点数を記録し、つまずいている生徒を早く見つけてフォローにつなげる。

- 使うのは三上1人（`mikami@soka.ed.jp`）。放課後に職員室のPCで、紙の答案から入力する
- 生徒・保護者・ほかの教員には公開しない

## 2. 使い方

アプリのURL：`https://kmkmkm-sk.github.io/（リポジトリ名）/`

### ログインする
1. アプリのURLを開く
2. 「Googleでログイン」を押す
3. 学校のアカウント（`mikami@soka.ed.jp`）を選ぶ
4. 右上にアドレスと「ログアウト」が出れば完了

使い終わったら、右上の「ログアウト」を押す。

### 点数を入力する
1. 「テスト」で今回のテストを選ぶ
2. 「クラス」でクラスを選ぶ
3. 「生徒」で最初の生徒を選ぶ（下の表の行を押してもよい）
4. 点数ボタンを押す（確認＝0〜3・欠、単元＝0〜10・欠）
5. 「送信」を押す
6. 自動で次の出席番号に進むので、4〜5をくり返す

- 下の表に、そのクラスの入力状況（入力済み 〇 / 〇人）が出る
- 表の「保存中…」は、保存が終わると消える
- 点数を直すときは、同じ生徒・同じテストでもう一度送信する（上書きされ、「前は 〇」と出る）

### 新しいテストを追加する
1. 画面下の「準備」を開く
2. 「種類」（確認／単元）と「何回目」を選ぶ
3. 「追加」を押す（名前と満点は自動で決まる。例：確認③、満点3）

### 名簿を取り込む（年度はじめ）
1. 名簿のスプレッドシートで、クラス・出席番号・生徒名の3列をコピーする
2. 「準備」の「名簿の取り込み」に貼り付ける
3. 「取り込む」を押す

同じ生徒（同じ年度・クラス・番号）は上書きされる。数字は半角で入れる。

## 3. ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体。画面・見た目・動きをすべてこの1ファイルにまとめている |
| `README.md` | この説明書 |

**`index.html` の中の設定値**（`<script>` の最初にある「ここを書き換えると設定が変わります」の部分）

| 名前 | 意味 | 今の値 |
|---|---|---|
| `YEAR` | 年度（名簿の絞り込みに使う） | `2026` |
| `TERM` | 学期（テストの絞り込みに使う） | `"2026-2"` |
| `CLASSES` | クラスの一覧 | `["1組", …, "5組"]` |

学期が変わったら `TERM` を、年度が変わったら `YEAR` と `TERM` を書き換える。

**生徒の名前や点数は、このリポジトリには入っていない。** ログインしたあと、Firestore（Googleのクラウド上のデータベース）から読み込む。

## 4. データの置き場所（Firestore）

| コレクション（データの箱） | 中身 | 1件の名前（ドキュメントID）の例 |
|---|---|---|
| `students` | 生徒名簿（年度ごとに1人1件） | `2026_112`（2026年度・1組12番） |
| `tests` | テストの回（学期ごとに1回1件） | `2026-2_kakunin_03`（2学期・確認③） |
| `scores` | 点数（生徒×回で1件） | `2026-2_kakunin_03_2026_112` |

- 「欠」は `status: "absent"`、点数は `score: null`（空）で保存する
- 確認平均と要注意の印は保存しない（表示するときに計算する。※一覧画面は未作成）

## 5. Firebase の設定場所

Firebase コンソール（`https://console.firebase.google.com`）→ プロジェクト `quiz-record-beta2026`

| 何を | どこで |
|---|---|
| 保存されたデータを見る・直す | 「Database と Storage」→「Firestore」→「データ」タブ |
| 誰が読み書きできるか（セキュリティルール） | 「Database と Storage」→「Firestore」→「ルール」タブ |
| ログインできるページの住所 | 「セキュリティ」→「Authentication」→「設定」タブ →「承認済みドメイン」 |
| ログインの方法（Google） | 「セキュリティ」→「Authentication」→「Sign-in method」タブ |
| 管理画面に入れる人 | 「設定」→「プロジェクトの設定」→「ユーザーと権限」 |
| 料金プラン | 左下の「Spark（無料）」。「アップグレード」は押さない |

**変えないこと**
- セキュリティルールの「使ってよい人」は `mikami@soka.ed.jp` だけ
- 使える人を広げるときは、ドメイン全体（`@soka.ed.jp`）ではなく、先生のアドレスを並べる方法にする（生徒も同じドメインのアカウントを持っているため）
- Firestore の場所は `asia-northeast1`（東京）。あとから変えられない

**公開リポジトリについて**
- `index.html` にある `apiKey` などは、パスワードではなくプロジェクトの住所のようなもの。公開してよい。データを守っているのはセキュリティルール
- 生徒の実名・点数・名簿ファイル（CSVなど）は、リポジトリに置かない

## 6. 開発を再開する手順

1. この README を読む
2. GitHub のリポジトリで `index.html` を開き、全文をコピーする
3. Claude のプロジェクト「小テスト記録アプリ」で、「今のコード」として貼る。セキュリティルールを変えるときは、Firebase の「ルール」タブの中身も貼る
4. 変えたいことを1つ伝える。Claude は「どこを変えたかの要約」→「変えたファイルの全文」の順で出す
5. GitHub で `index.html` を開き、鉛筆アイコン（Edit）を押す → 中身をすべて消して、受け取った全文を貼る →「Commit changes」を押す
6. 1〜2分待ってから、アプリのURLを再読み込みする（GitHub Pages への反映に少し時間がかかる）
7. テスト観点表の、変更に関係する項目を試す
8. 変えた内容をこの README に反映する

エラーが出たら、画面の赤字、または F12 キー →「Console」タブの赤字をそのまま貼って伝える。
（「Cross-Origin-Opener-Policy …」という注意書きは、ログインできていれば無視してよい）
